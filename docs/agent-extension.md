# אפיון טכני — אייג'נט הדפדפן "שתי נגיעות"

מסלול א' מה-PRD: תוסף כרום שממלא את מסכי שידור הדוח השנתי (1301) באתר רשות
המסים מתוך "קובץ תיק" מאומת, בדפדפן של המשתמש בלבד.

## ממצא המפתח (מהפיילוט)

מערכת השידור (`secapp.taxes.gov.il/shdochshana1301/*`) משתמשת בקונבנציית
מזהים יציבה שנגזרת ישירות מקודי השדות הרשמיים של הטופס:

| אלמנט | תבנית מזהה | דוגמה |
|---|---|---|
| שדה סכום | `txt<קוד שדה>` | `txt158`, `txt244`, `txt042` |
| תיבת סימון | `chk<קוד>` | `chk020`, `chk021` |
| טבלת ילדים | `txt<שורה>_<עמודה>` | `txt260_4_5`, `txt260_6_17`, `txt260Nolad` |

המשמעות: מפת המילוי לא תלויה במבנה ה-DOM או בעיצוב — רק בקודי השדות,
שהם חלק מהטופס הרשמי ולא השתנו שנים. נקודת שבירה יחידה: שינוי קונבנציה
מערכתי (נדיר; מזוהה מיידית ע"י ניטור).

המסכים הממופים (אומתו מול המערכת בפועל, 07/2026):

| מסך | URL | טיפול |
|---|---|---|
| פרטים כלליים | `frmPratimKlalim_<שנה>.aspx` | הנחיה ידנית (בחירות רדיו מורכבות) |
| פירוט הכנסות | `frmTofes1301_<שנה>.aspx` | מילוי אוטומטי מלא |
| תוצאות חישוב | `frmResult.aspx` | קריאת תוצאה + אימות מול צפי |

- **אפס רשת:** לתוסף אין host permissions מלבד `secapp.taxes.gov.il`, אין
  קריאות fetch, והתיק נשמר ב-`chrome.storage.local` בלבד.
- **אפס הזדהות:** התוסף רץ בתוך סשן שהמשתמש פתח בעצמו. אין נגיעה בסיסמאות,
  עוגיות או טוקנים.

## פורמט קובץ התיק

נוצר ע"י `lib/extensionCase.ts` באפליקציה (כפתור "הורד קובץ תיק לתוסף"):

```json
{
  "version": 1,
  "taxYear": 2025,
  "reportScope": "joint",
  "fields": { "158": 534893, "194": 20373, "244": 356026, "248": 52799,
              "011": 364, "045": 21362, "036": 3508, "042": 147493 },
  "checkboxes": ["020", "021"],
  "children": { "260": { "age4_5": 1, "age6_17": 1 } },
  "expectedRefund": 16273
}
```

`expectedRefund` הוא לב שער הבטיחות במסך התוצאות.

## עקרונות בטיחות (מקודדים, לא רק מוצהרים)

1. **אין שידור אוטומטי.** ל-content script אין שום נתיב קוד שלוחץ על כפתור
   שידור/אישור. המילוי נגמר בשדות; הקליק האחרון של המשתמש.
2. **מילוי דרך אירועים אמיתיים.** `setValue` יורה `input` + `change` (חובה
   ב-ASP.NET WebForms כדי שוולידציות הדף ירוצו), וסימוני checkbox נעשים
   ב-`click()` כדי להפעיל את ה-handlers של הדף.
3. **אימות אחרי כתיבה.** כל שדה נקרא חזרה מה-DOM ומושווה לתיק; פערים
   מסומנים אדום בדף וביומן. (הלקח מטעויות ההקלדה בפיילוט: 53,893/534,893.)
4. **שער חוב במסך התוצאות.** `readResult` מפרסר את "מס לאחר ניכוי במקור":
   - תוצאה חיובית (חוב) → ⛔ "אל תשדר"
   - סטייה מעל 10% מהצפי → ⚠️ "בדוק לפני שידור"
   - התאמה → ✓ "אפשר לשדר"
5. **שקיפות.** כל שדה שמולא מסומן ויזואלית (מסגרת ירוקה) והיומן ב-popup
   מפרט כל פעולה.

## מה בנוי עכשיו (שלד עובד)

- `extension/manifest.json` — MV3, מוגבל ל-secapp בלבד
- `extension/fieldmap.js` — מפת 3 מסכים, ‎30+ שדות סכום, טבלת ילדים
- `extension/content.js` — זיהוי מסך, מילוי, אימות, קריאת תוצאה
- `extension/popup.html/js` — טעינת תיק, תוכנית מילוי, יומן, פסקי דין
- אינטגרציה באפליקציה: `lib/extensionCase.ts` + כפתור הורדה ב-StepResults

התקנה לפיתוח: `chrome://extensions` → Developer mode → Load unpacked →
בחירת תיקיית `extension/`.

## פערים ידועים / צעדים באים

| פער | עדיפות | כיוון |
|---|---|---|
| מסך "פרטים כלליים" ממולא ידנית (רדיו-באטנים מרובים) | גבוהה | לכידת מזהי הרדיו מסשן אמיתי → הרחבת המפה |
| מסך "פרטים אישיים" (בנק, כתובת) טרם מופה | גבוהה | כנ"ל — נדרש דגימת HTML אחת מהמסך |
| העלאת מסמכים במערכת | בינונית | כנראה נשאר ידני (file inputs מוגנים) — הנחיה בלבד |
| טבלת עמדות/שדות דינמיים (סעיף טז) | נמוכה | לא רלוונטי לשכירים |
| ניטור שבירת מפה | גבוהה | בדיקת probe שבועית + טלמטריית "שדה לא נמצא" (אנונימית, opt-in) |
| e2e בדיקות | בינונית | Playwright מול עותק HTML שמור של המסכים (fixtures מהפיילוט) |
